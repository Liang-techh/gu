# 蛊真人 simulation-first RPG 架构

## 核心原则

玩家不是在一棵剧情树上选择下一页，而是在一组持续运行的状态上采取行动。小说原文提供青茅山、开窍大典、方源、方正、学堂、家族和遗藏等内容素材；引擎只提供通用规则，让这些素材在状态变化中重新组合。

```text
输入 / UI / 将来的 AI 意图
          ↓
安全意图解析（只生成 command，不改状态）
          ↓
SimulationKernel.dispatch
          ↓
Action + Event + Component Systems
          ↓
WorldState（时钟、实体、组件、记忆、关系、势力、导演）
          ↓
Projection / UI / 存档 / 日志
```

## 状态模型

`entities[id]` 是统一实体表。玩家和 NPC 都使用相同的组件形状。`src/engine.js` 提供类似 Qud `Parts` 的组件查询、类似 `Events` 的领域事件流，以及可注册的 GoalHandler 和 InteractionHandler；`simulation.js` 只是当前世界规则的一个实现，而不是把扩展点锁死在 UI 或剧情文本里。

组件默认值由 `src/entity.js` 的实体工厂集中创建，区域人口构建器只注入内容种子。这样新增 NPC、敌对生物或未来的非人实体时，可以复用同一身体、需求、记忆和能力组件，而不需要在世界规则里复制一份对象形状。

世界内容位于独立的 `src/content.js` 内容包，并带有 `CONTENT_INDEX` 与版本号。当前内容包已经从青茅山扩展到白骨山、商家城、三叉山、天梯山、第三卷北原区域链、第四卷狐仙福地—中洲链路、第五卷首批五域战争区域链，以及第六卷首批两天终局区域链。地点、人口表、势力、人物、蛊虫和原文来源因此可以逐包替换或增加；存档记录内容包 ID，避免规则版本和世界素材无声漂移。

`scripts/check-content.cjs` 对内容包做只读结构检查：地点图必须闭合、人口表和势力引用必须存在、NPC 日程不能指向未知区域、委托/对话不能引用失效对象，所有原文来源路径必须存在。这样扩展小说世界时，内容错误会在运行前暴露，而不是等玩家走到断裂的地点或对话才出现。

`scripts/audit-long-run.cjs` 以固定种子无头运行至第 365 日，检查实体位置、需求/身体数值、区域资源、事件队列/账本、历史快照和存档恢复的边界。这是世界模拟的稳定性门槛，不等同于剧情覆盖率或数值平衡证明。

`src/action-catalog.js` 是命令定义层。它根据玩家位置、区域状态和重复系统是否开放生成可用 actions；UI 只渲染这些 command，不再复制演武、传承、巡逻、真阳楼和拍卖会的条件。自然语言解析和未来 AI 导演可以复用同一个目录，从而把“能做什么”从界面逻辑提升为世界规则的一部分。

`src/director.js` 是导演运行时层：它只负责从已注册规则中发现候选事件、把事件交给注册的处理器、验证玩家选择并推进时钟。小说内容的导演规则仍可独立增加，运行时不需要知道具体是狼潮、三王传承还是宗门压力。

当前内容包的 30 个导演候选位于 `src/gu-director-rules.js`。每条规则只声明 `when`、优先级、事件类型、小说来源和可选行动；它通过注册表进入导演运行时，因而可以替换或叠加不同卷章内容，而不需要把候选事件重新写进模拟内核。事件选择后的状态结算仍由内容事件处理器负责，保持“发现局势”和“结算后果”的边界。

对应的 `src/gu-event-rules.js` 只注入引擎、时间、内容来源、实体激活、关系、记忆、日志和推进回调，注册 30 个事件结算处理器。事件处理器可以修改小说世界的势力、资源、旗标和跨卷战争状态，但不需要拥有 `dispatch`、存档或 UI 的控制权。

`src/intent.js` 把自然语言输入转换成 command，不直接修改状态。地点别名集中维护并覆盖整个当前内容地图；真正的可达性、资源、前置旗标和行动成本仍由 simulation kernel 校验，因此“能理解意图”和“世界允许行动”保持分离。

区域初始化由 `src/zone-builder.js` 负责：地点标签决定基础资源和危险度，人口表决定环境居民，构建器接收随机源和实体工厂而不依赖 UI。以后可以为不同内容包替换区域构建策略，或在存档恢复/新区域生成时重复调用同一规则。

`src/history.js` 单独维护历史账本：重大领域事件进入有限长度的历史序列，跨日时保存势力和区域快照，UI 只读取摘要。这样日志可以滚动、界面可以更换，而世界发生过什么仍然是存档中的一等状态。

## 系统管线

`src/engine.js` 还提供按阶段注册的 system registry。当前每个小时依次运行 `conditionTick`、`playerNeeds` 和 `npcSimulation`，跨过世界日时运行 `worldDailyTick`，再由导演观察完整的结算结果。系统有明确优先级，因而新增生产、疾病、天气、追捕或区域生态系统时，不必继续把规则塞进单一 `advance()` 分支；同一管线也能被测试、回放和未来的批量世界模拟调用。

实体还可以拥有运行时 `conditions.active` 状态效果。`src/condition.js` 提供状态的附着、刷新、查询、移除和计时；当前威胁会附着 `afraid`，冲突会附着 `wounded`，小时系统负责过期事件，NPC 目标选择会优先响应恐惧。这是对 Qud Parts/Events 边界的轻量抽象：状态不是一次性文本，而是可以被多个系统观察的组件。

`src/knowledge.js` 把记忆中的事实进一步结构化为 `value / confidence / kind / clock / source / provenance`，并维护每个实体对其他实体的 `suspicion` 与身份 `masks`。传闻默认低置信度，亲历观察和秘密线索置信度更高；怀疑度达到阈值后，NPC AI 会优先调查、观察或避开玩家。这样“谁知道什么”成为世界状态，而不只是日志文本。

`src/identity.js` 在知识组件之上提供可运行的身份层：每个实体都有真实身份和若干公开面具，面具拥有公开姓名、角色、强度、覆盖故事、穿戴时间与已知者集合。玩家可以在行动目录或自然语言中切换“无名散修”面具、恢复真名或向同地点 NPC 摊牌；摊牌只改变目标 NPC 的知识，不会把真相广播给整个世界。市场事件可以记录面具痕迹，导演再根据追踪压力生成调查事件；调查压力同时进入相关势力的 NPC 目标评分，形成“传闻→案件→调查/伏击”的反馈回路。

动作也通过同一运行时注册。当前委托接受/交付、商家城演武、三王传承闯关、北原巡逻、真阳楼闯层和内容驱动对话已经由 Action Registry 调度；未迁移的基础动作仍走兼容分支。迁移策略是先把有独立资源、事件和失败后果的动作注册化，再逐步消除旧的条件链。

对话定义位于内容包的 `CONVERSATION_DEFS`，由 `src/conversation.js` 根据地点、旗标、时间和关系门槛筛选。选项后果不直接操作 UI，而是通过关系、势力、记忆和 History 账本写入世界状态。

委托定义同样只保留在内容包的 `CONTRACT_DEFS`；`src/contracts.js` 负责发现、目标判定、接受、完成和奖励。主模拟器只注入时间、关系、记忆、日志和推进回调，因此委托运行时可以被其他内容包复用。

重复行动也遵循同一边界。`src/repeatable-systems.js` 只接收引擎、随机源、关系/记忆/日志、伤害和时间推进回调，向主模拟器提供演武、传承、巡逻、闯楼、拍卖和梦境探索运行时。它们的资源、失败、领域事件和长期后果仍写入同一份世界状态，因此可以被 UI、自然语言意图和 AI 导演共享，而不会重新形成主模拟器的条件分支。

领域事件由 `src/engine.js` 同时写入待处理队列和有限长度的 `events.recent` 账本。队列用于即时监听与消费，账本用于存档、回放和 UI 查询，避免“事件已处理”被误解成“事件从世界消失”。`src/rumor.js` 订阅事件总线，把同地点的交互、冲突、资源争夺和战线变化转成旁观 NPC 的记忆事实，并沿事件参与者所属势力的关系网传播；每次传播会保存 `eventId`、势力路径和置信度，并在 `state.intel.cases[subjectId].factions` 中积累案件压力。记忆因此可以通过空间和社会组织传播，而不要求每个 NPC 都直接参与行动。

第二卷的演武场和三王传承使用持续系统而不是一次性分支：`arena` 保存比赛、胜负、连胜和声望；`inheritance` 保存尝试次数、轮次、难度、发现和完成状态。第三卷的北原巡逻和真阳楼、第四卷的福地/宗门/拍卖链路、第五卷的 `worldWar` 五域战争状态同样保存跨区域状态。每次行动都经过同一个 dispatch、资源、伤势、记忆和历史管线。

第六卷终局链路使用独立的 `eternalWar` 状态保存神帝城、人道战线、两天重叠、疯魔窟、梦境压力、宇宙热度和星宿安排是否已经展开；梦境探索是可重复行动，不会被一次导演事件消费掉。

拍卖会的导演事件只负责打开市场，之后由 `auction_lot` ActionHandler 处理重复行动。玩家可以竞拍、观察行情、出售情报、抬价、抵押借元石或核验传闻；价格同时受热度和稀缺度影响，市场会记录供给、债务、信誉、情报可信度和交易追踪压力。每次行动都通过 `auction.lot` 领域事件更新区域活动、势力张力、旁观 NPC 传闻和玩家知识组件；这使“拍卖会”成为一个会自行变化、且会暴露行动者意图的系统，而不是一次性文本节点。

当面具下的交易痕迹达到阈值，内容导演规则包会生成 `identityPursuit` 调查局势。它不是预写的追杀分支：事件由 `central.tracePressure`、当前面具和冷却状态共同触发，结算仍通过统一事件注册表，结果可以降低追踪、污染情报可信度，或把市场和宗门紧张度推向更高层。

`src/pursuit.js` 把调查压力进一步物化为追捕队。队伍保存势力、目标、成员、线索置信度、推进度、热度和接触次数；成员拥有 `agent` 组件，是可以在地图上寻路、被观察、被收买或被误导的普通世界实体。小时系统独立推进追捕队，NPC 通用 AI 跳过 `agent`，避免代理人同时执行两套移动规则；玩家接触行动仍经过统一 Action Registry 和事件账本。

`src/agency.js` 提供另一种代理关系：玩家不用亲自执行每个行动，可以委托同地点 NPC 完成打探情报、侦查地点、代为交易或游说势力。委托保存代理人、目标地点、成本、进度、质量、截止时间和结果；代理人的当前位置、精力、人格、关系和所属势力都会影响结算。委托结果通过 `agency.commission_created` / `agency.commission_completed` 领域事件进入传闻、知识和 History，而不是直接把奖励写给玩家。

`src/market.js` 把交易从单个剧情动作提升为共享世界系统：清水、食物、月兰花瓣和遗藏碎片拥有基础价、供给、需求和价格；NPC 的 `trade` 目标与玩家的“代为交易”委托调用同一个 `quote/trade` 结算路径，直接改变库存、元石、供需、区域活动和势力影响。交易事件进入普通传闻和 `state.market.transactions`，但其案件压力为零，避免把日常商业活动错误升级成追杀线索；只有身份暴露、暴力和高风险市场痕迹才会推动追捕系统。

玩家和 NPC 都使用相同的组件形状：

- `identity`：名字、角色、标签。
- `position`：地点。
- `needs`：精力、饥饿、安全感。
- `cultivation`：资质、境界、阶段、真元、修为。
- `personality`：野心、谨慎、忠诚、贪欲、好奇。
- `schedule`：默认日程，不是强制剧本。
- `goals`：当前目标与候选目标。
- `memory`：事实索引和带时间/情绪的事件记忆。
- `inventory`：资源和蛊虫组件。
- `body`：生命、伤口和部位耐久；冲突系统只能通过伤害事件修改它。
- `abilities`：蛊术与技能能力槽，供行动系统消耗和验证。

NPC 行为运行时位于 `src/npc-ai.js`。它只依赖组件查询、地点图、时钟、随机源和 GoalHandler 回调：先把恐惧、饥饿、安全感、性格、势力紧张、玩家关系和近期目标历史转换成效用分数，再沿地点图移动，最后执行目标并记录遭遇记忆。具体的 `secureResources`、`prepareAlliance` 等目标仍由内容规则注册，因此同一 AI 层可以服务青茅山 NPC、北原部族或未来其他内容包；`goals.history` 会降低短期重复目标，避免 NPC 只按数组轮询。

`src/default-goals.js` 提供内容包所需的通用目标处理器，例如学习、采集、巡逻、调查、招募、备战、疗伤和调停。它们会修改区域资源、危险度、势力影响、需求或记忆；`check-content` 会验证人口表和 NPC 种子中的每个目标都存在对应处理器。

`src/ability.js` 负责实体能力的学习、可用性和发动。蛊虫炼化完成后写入实体的 `abilities.gu`，战斗只请求能力运行时并消费真元，再通过 `ability.used` 领域事件写入历史；新增蛊虫不需要复制一整段战斗条件分支。

`factions` 和 `relationships` 独立保存，不能通过截断日志重建。这样玩家帮助方正、威胁漠北、向家族报告遗藏等动作，才会成为后续世界的事实，而不是一行已经消失的文字。

NPC 目标选择还会读取所属势力的紧张度和态度：战争压力高时，拥有对应目标的 NPC 会优先备战或巡逻；势力敌对时会优先规避玩家。势力因此不仅是 UI 数值，也会反向改变世界中人物的行为。

地点不是静态背景。`zones` 保存资源、天气、危险度、活动度、访问量和人口规模；人口表按地点类型生成环境居民，让竹林、河滩、商队营地和山寨在没有剧情事件时也能自行运转。资源采集、NPC目标和跨日恢复共同改变区域状态。

## 时间与 NPC

每个合法行动推进小时。时间推进触发：

1. 玩家需求、真元和修为恢复/消耗。
2. NPC 根据日程移动。
3. NPC 根据饥饿、恐惧、野心和世界压力选择当前目标。
4. 同场遭遇写入 NPC 记忆。
5. 跨日后结算需求、势力紧张度、导演压力和记忆衰减。

日程是“默认行为”，记忆和关系可以覆盖它；这使 NPC 不是静态对话点。导航系统在地点图上计算路径，每个行动周期只前进一个区域，因此跨地点目标不会瞬移，也不会因为不是直接邻居而失效。

NPC 目标还必须产出世界侧结果：采集会改变资源与势力影响，追查遗藏会增加共享压力，交易会改变商路活动，竞争会提高家族紧张度。日志只是这些事件的投影，不能代替状态本身。

## 事件和 AI 导演

事件分为两类：

- `action`：玩家提出的明确动作，由规则验证并结算。
- `director_event`：导演观察世界条件后生成的局势节点，例如竹林酒香、学堂竞争、商队消息。
- `combat`：实体间的连续冲突；攻击写入身体部位、伤口、死亡和对方记忆。

规则事件会写入带持久 `sequence` 的 `events.pending` 领域事件流，例如 `world.travel`、`npc.goal_action`、`social.interaction` 和 `combat.damage`。队列只保留最近窗口，但序列号不会回绕；外部导演、调试器或未来的回放系统可以消费这些事件，不需要解析 UI 日志。注册动作还支持 `before/after` hooks，当前用于记录动作指标，未来可以接入通用消耗、权限、冷却和反应规则。

运行时还提供事件监听器注册表。事件发出后，监听器可以为区域活动、危险度或统计账本添加派生后果；例如移动事件由区域访问监听器结算，演武和传承事件由各自的区域压力监听器结算。监听器不替代持久事件队列，而是把 Qud 式事件边界变成可组合的规则扩展点。

导演不能直接写玩家数值。它会先收集所有满足条件的候选规则，再按 `priority + score(state,event)` 选择，支持存档中的规则冷却与导演历史；`resolve_event` 仍经过同一个状态结算入口。当前导演已经覆盖遗藏线索、学堂竞争、商队进入、贾富拍卖会、三寨议事、狼潮逼近、三族大比武和铁家调查；后续五域与两天终局链也使用同一候选评分运行时。这些事件由时间、地点、势力紧张度、资源压力共同触发，而不是按章节顺序强制播放。将来接入语言模型时，模型只能生成候选意图/文案，不能绕过 `dispatch`。

## 小说迁移策略

第一阶段只迁移原文中有明确依据的青茅山开局：

- 方源重生与开窍大典前夜；
- 方正的孪生兄弟关系；
- 古月学堂、家老、竞争者和家族培养；
- 竹林、酒香、月光蛊、酒虫和花酒遗藏线索。
- 商队提前进入青茅山、贾富的市场博弈、三寨联盟和狼潮前的资源危机。
- 第二卷首批区域链：白骨山旅途、商家城演武场、三叉山三王传承、天梯山狐仙福地传闻。
- 第五卷首批区域链：影宗残脉重建、南疆超级家族、西漠房家、东海节点、天庭与长生天；五个跨域导演事件将它们接入持续战争热度和势力张力。
