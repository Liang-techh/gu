# 蛊真人 simulation-first RPG 架构

## 核心原则

玩家不是在一棵剧情树上选择下一页，而是在一组持续运行的状态上采取行动。小说原文提供青茅山、开窍大典、方源、方正、学堂、家族和遗藏等内容素材；引擎只提供通用规则，让这些素材在状态变化中重新组合。

```text
输入 / UI / 将来的 AI 意图
          ↓
安全意图解析（只生成 command，不改状态）
          ↓
SimulationKernel.dispatch
          ↓
Action + Event + Component Systems
          ↓
WorldState（时钟、实体、组件、记忆、关系、势力、导演）
          ↓
Projection / UI / 存档 / 日志
```

## 状态模型

`entities[id]` 是统一实体表。玩家和 NPC 都使用相同的组件形状。`src/engine.js` 提供类似 Qud `Parts` 的组件查询、类似 `Events` 的领域事件流，以及可注册的 GoalHandler 和 InteractionHandler；`simulation.js` 只是当前世界规则的一个实现，而不是把扩展点锁死在 UI 或剧情文本里。

组件默认值由 `src/entity.js` 的实体工厂集中创建，区域人口构建器只注入内容种子。这样新增 NPC、敌对生物或未来的非人实体时，可以复用同一身体、需求、记忆和能力组件，而不需要在世界规则里复制一份对象形状。

世界内容位于独立的 `src/content.js` 内容包，并带有 `CONTENT_INDEX` 与版本号。`src/gu-world.js` 是该内容包的 world provider，负责把地点、人口、势力、人物、开场局势和延迟激活种子装配成初始 WorldState；kernel 不再直接创建青茅山世界。当前内容包已经从青茅山扩展到白骨山、商家城、三叉山、天梯山、第三卷北原区域链、第四卷狐仙福地—中洲链路、第五卷首批五域战争区域链，以及第六卷首批两天终局区域链。地点、人口表、势力、人物、蛊虫和原文来源因此可以逐包替换或增加；存档记录内容包 ID，避免规则版本和世界素材无声漂移。

`src/gu-state.js` 是配套的 state provider，负责蛊真人内容包的存档默认值、组件修复、数值边界和区域状态归一化。kernel 只调用 `stateNormalizer.normalize(state)`，因此替换世界时不需要把另一套内容 schema 塞回时间、dispatch 或存档管线。

### 势力不是数值，而是可破裂的承诺网络

单独的 `factions[id].attitude / tension / influence` 只能表达“某势力现在怎么看”，不能表达小说后期更有爽点的“谁为了什么暂时站在谁一边”。`src/faction-pacts.js` 因此提供一个独立的 coalition ledger：

```text
coalitions
  ├─ pacts[pactId]
  │    ├─ members[]
  │    ├─ legitimacy       盟约能否被各方承认
  │    ├─ cohesion         成员愿意共同承担风险的程度
  │    ├─ supply           承诺是否有资源兑现
  │    ├─ obligations{}    每个成员尚未履行的义务
  │    └─ history[]        撮合、兑现、揭露、倒戈的可回放记录
  └─ history[]             跨盟约倒戈与承诺变更索引
```

盟约由后期事件、NPC 目标和玩家外交行动共同创建，而不是只能由剧情节点创建。日级 `coalitionTick` 读取战区压力、梦境污染、影宗暴露、市场活动、势力关系与紧张度，逐日更新补给、信誉和凝聚力；低于阈值时进入 `strained`，资源/合法性/凝聚力同时断裂时自动选出承压最低的一方退出，并写入 `faction_defection` 后果、NPC 记忆、领域事件和导演压力。玩家也可以在同一管线里撮合、兑现、曝光或倒戈。这样“联盟”成为一个会被世界检验的资产，倒戈是模拟结果而非布尔剧情 flag。

内容包还实现了春秋蝉式高代价逆转：`spring_autumn_reset` 只有在濒死绝境且仍有逆流次数时可用。它重建一份新的 WorldState，消耗当前资源和一次次数，改变种子与身体上限，并把有限的旧世界事实降级为带来源、低置信度的 `futureEchoes`；这不是无成本读档，而是新的世界变量和新的信息优势。

三王传承也不再是单一随机成功率：`inheritance_scout` 写入线索类型与可信度，推进动作读取资格和线索质量，`greed` 模式换取额外遗藏但增加竞争者推进与暴露，失败记录错误路线、伤势和持久后果；开放窗口与竞争者进度保存在 `state.inheritance`，不依赖 UI 文本。

狼潮与三寨联盟使用 `state.wolfCrisis` 作为持续危机账本：联盟合法性、各方贡献、补给、压力、战斗、伤亡和迁徙由日级 `wolfCrisisTick` 推进。`wolf_action` 提供救援、侦查和囤积三种互相牵制的行动；囤积会改善个人储备却恶化公共补给和势力张力，补给不足会把环境居民迁往商队营地并写入持久后果。

市场灾害使用 `state.marketShock` 和 `marketShockTick`，而不是一条一次性灾难文本：供给损失、价格冲击、救济投入、套利痕迹、迁徙人数和恢复阶段都会持续结算。`market_shock_action` 将救济、套利、核验暴露为自由行动。`src/knowledge.js` 对同一事实保留 `alternatives`，强观察可以覆盖低置信度传闻但不会删除旧版本；`src/rumor.js` 按传播路径写入 `rumorConfidence / requiresVerification / rumorDistorted`，因此 NPC 不会直接读取世界真相。

狐仙福地使用独立的 `state.blessedLand` 基地账本：资源、魂魄储备、守备、驻民、声望、维护成本、升级和宗门压力在跨日与离线推进中持续变化。回归事件只负责打开基地与设置初始局势，`blessedLandTick` 负责生产、维护、守备衰减和驻民迁徙；资源/守备过低时，驻民会离开福地并留下持久后果，守备与资源充足时则会反向压低宗门压力。`blessed_land_action` 把加固、培育、招募和隐藏变成可自由重复的基地经营动作，避免“狐仙福地”退化为一次性剧情旗标。

五域战争使用 `state.worldWar.fronts` 作为战区级代理状态，而不是只增加 `worldWar.heat`：每个战区记录补给、压力、控制权、战斗次数、伤亡、指挥者和两侧势力。`worldWarTick` 在跨日/离线时消耗后勤、积累压力并自动爆发战斗；战斗会创建操作记录、写入指挥者记忆、改变势力张力并进入持久后果账本。`front_action` 为玩家暴露同一套战区接口：补给支援、情报侦查、破坏和调停都会改变战区，而不是只奖励一段文本。这样南疆、西漠、天庭等区域可以先独立运行，再由导演根据战区状态选择下一次冲突。

NPC 的 `prepareWar`、`protectClan`、`patrol` 和 `mediate` 目标也会识别当前位置的开放战区：补给筹备、守护、巡逻和调停直接修改战区账本，并写入目标事件与 NPC 记忆。这样 Qud 式 Brain/GoalHandler 的“目标执行”才真正反馈到跨区域世界，而不是只在 `goals.history` 中显示完成。

影宗重建使用 `state.shadowNetwork` 表示隐秘组织，而不是一个 `shadowSectRebuilt` 布尔值：遗址、狐仙福地和中洲分别成为可启用的网络节点，节点有控制、补给和隐蔽性；网络整体有凝聚力、资源、招募、情报、可见度、暴露度和背叛次数。`shadowNetworkTick` 会继续消耗维护资源、交换情报、积累暴露并在节点崩溃时留下后果；影无邪或其他 NPC 执行 `rebuildShadow` 会改变节点，而玩家可以通过 `shadow_network_action` 扩张、取情报、隐藏或出卖暗线。这把“重生者依据自己的记忆重建敌对组织”转成可以被不同玩家路径重新组合的持续代理系统。

导演现在也可以读取持续系统产生的状态阈值：`shadowNetworkExposure` 不绑定某个固定章节，而是在网络暴露度达到阈值、玩家处于暗线节点且没有冷却时生成。事件选择通过同一个事件注册表处理抹痕、套利、举报或忽略，后果回写网络、势力、玩家记忆和持久后果账本。这是 Qud 式“世界先运行，导演再对异常状态作出反应”的边界。

梦境战场使用独立的 `state.dreamRealm` 账本，不再把梦境等同于 `eternalWar.dreamPressure`：三类势力拥有可变化的控制份额，梦境有资源、污染、争夺压力、周期行动和操作记录。`dreamRealmTick` 在玩家不操作时重算势力份额、资源和污染，并让梦境中的 NPC 学习目标参与争夺；`dream_dive` 与 `dream_realm_action`（建立锚点、收割、稳定、破坏）共用同一事件/记忆/后果管线。梦境因此成为一个会被多方经营和反向污染现实的区域，而不是一次性高成功率检定。

`scripts/check-content.cjs` 对内容包做只读结构检查：地点图必须闭合、人口表和势力引用必须存在、NPC 日程不能指向未知区域、委托/对话不能引用失效对象，所有原文来源路径必须存在。这样扩展小说世界时，内容错误会在运行前暴露，而不是等玩家走到断裂的地点或对话才出现。

`scripts/audit-long-run.cjs` 以固定种子无头运行至第 365 日，检查实体位置、需求/身体数值、区域资源、事件队列/账本、历史快照和存档恢复的边界。这是世界模拟的稳定性门槛，不等同于剧情覆盖率或数值平衡证明。

`src/action-catalog.js` 是命令定义层。它根据玩家位置、区域状态和重复系统是否开放生成可用 actions；UI 只渲染这些 command，不再复制演武、传承、巡逻、真阳楼和拍卖会的条件。自然语言解析和未来 AI 导演可以复用同一个目录，从而把“能做什么”从界面逻辑提升为世界规则的一部分。

`src/director.js` 是导演运行时层：它只负责从已注册规则中发现候选事件、把事件交给注册的处理器、验证玩家选择并推进时钟。小说内容的导演规则仍可独立增加，运行时不需要知道具体是狼潮、三王传承还是宗门压力。

当前内容包的 30 个导演候选位于 `src/gu-director-rules.js`。每条规则只声明 `when`、优先级、事件类型、小说来源和可选行动；它通过注册表进入导演运行时，因而可以替换或叠加不同卷章内容，而不需要把候选事件重新写进模拟内核。事件选择后的状态结算仍由内容事件处理器负责，保持“发现局势”和“结算后果”的边界。

对应的 `src/gu-event-rules.js` 只注入引擎、时间、内容来源、实体激活、关系、记忆、日志和推进回调，注册 30 个事件结算处理器。事件处理器可以修改小说世界的势力、资源、旗标和跨卷战争状态，但不需要拥有 `dispatch`、存档或 UI 的控制权。

`src/intent.js` 把自然语言输入转换成 command，不直接修改状态。地点别名集中维护并覆盖整个当前内容地图；真正的可达性、资源、前置旗标和行动成本仍由 simulation kernel 校验，因此“能理解意图”和“世界允许行动”保持分离。

区域初始化由 `src/zone-builder.js` 负责：地点标签决定基础资源和危险度，人口表决定环境居民，构建器接收随机源和实体工厂而不依赖 UI。以后可以为不同内容包替换区域构建策略，或在存档恢复/新区域生成时重复调用同一规则。

`src/zone-runtime.js` 在构建器之上实现 Qud 式区域生命周期。当前玩家所在区域保持 `active`，离开区域后进入 `suspended`；每个区域记录 `lastActiveClock`、`lastCachedClock`、`lastPlayerPresence`、`lastSettlementClock` 和有界 `queuedEvents`。前台区域按每日详细规则推进，后台区域根据离线小时数做确定性摘要结算，更新活动度、危险度、资源产出和冲突摘要；重新进入时先结算自上次缓存以来的时间，再恢复为活跃区域。这样“离开后世界继续运行”不再依赖 UI 是否还显示那张地图。后台居民还会执行 `trade/patrol/guard/forage/prepareWar` 等目标：交易调用同一个市场运行时，巡逻、备战和冲突改变区域与势力状态，冲突通过同一个伤害入口留下记忆、事件 provenance 和持久后果。完整的区域对象流式加载和逐实体卸载仍可在此生命周期边界上继续扩展。

区域实体驻留由同一运行时管理：环境实体在非活跃区域会从 `state.entities` 卸载到 `state.entityCache`，区域只保留 `loadedIds/cachedIds` 索引和离线摘要；玩家进入时按地点水合回完整实体。玩家、命名 NPC 和追捕/委托代理目前属于跨区域持久实体，保持可被关系、委托和追捕系统直接引用；环境居民则遵循活跃区域精算、非活跃区域缓存的边界。

`src/history.js` 单独维护历史账本：重大领域事件进入有限长度的历史序列，跨日时保存势力和区域快照，UI 只读取摘要。这样日志可以滚动、界面可以更换，而世界发生过什么仍然是存档中的一等状态。事件本身由 `src/provenance.js` 生成可序列化的来源记录，保存来源、行动者、目标、地点、父事件和标签；导演事件结算期间发出的领域事件会自动挂接到当前局势节点。

## 系统管线

`src/engine.js` 还提供按阶段注册的 system registry。`src/gu-systems.js` 将每个小时的 `conditionTick`、`effectTick`、`playerNeeds`、追捕、NPC AI、代理人推进，以及每个世界日的市场、NPC 恢复、区域离线结算、家族压力、北原补给、五域战争、终局战争和历史快照分别注册并排序，导演在完整结算后观察世界。系统有明确优先级，因而新增生产、疾病、天气、追捕或区域生态系统时，不必继续把规则塞进单一 `advance()` 或 `dailyTick()` 分支；同一管线也能被测试、回放和未来的批量世界模拟调用。

实体还可以拥有运行时 `conditions.active` 状态效果。`src/condition.js` 提供状态的附着、刷新、查询、移除和计时；当前威胁会附着 `afraid`，冲突会附着 `wounded`，小时系统负责过期事件，NPC 目标选择会优先响应恐惧。这是对 Qud Parts/Events 边界的轻量抽象：状态不是一次性文本，而是可以被多个系统观察的组件。

在此之上，`src/effect.js` 提供 Qud `EffectRack` 的通用实例层：效果拥有独立 `kind/id`、持续时间、强度、来源、叠加策略、数据载荷和 `onApply/onRefresh/onTick/onExpire/onRemove` 生命周期。当前冲突会给每次命中附着可叠加的 `wound` 效果，危险地形由 `src/gu-effects.js` 注册 `environmentExposure` 与 `terrainFatigue`，小时系统逐实体推进并发出效果生命周期事件；因此“伤势”“暴露”“疲劳”“中毒”“蛊虫反噬”“临时增益”可以共用同一运行时，而不必继续扩张条件或战斗专用分支。`src/combat.js` 是统一战斗解析器：玩家攻击/蛊术/防守/脱身回合、环境伤害、离线冲突和活跃 NPC 伏击都经由同一个 `damage/exchange` 入口，自动写入部位、伤势、死亡、记忆、事件 provenance 和持久后果；NPC 额外使用 pair cooldown，避免同一小时重复交换。战斗回合由 Action Registry 注册，`simulation.js` 不再保留玩家战斗分支。

`src/knowledge.js` 把记忆中的事实进一步结构化为 `value / confidence / originConfidence / kind / clock / source / provenance`，并维护每个实体对其他实体的 `suspicion` 与身份 `masks`。传闻默认低置信度，亲历观察和秘密线索置信度更高；知识按世界时间衰减但不会立即抹除，强观察可以重新提高其置信度。`observeZone` 将资源、危险和观察时刻写入实体所在地点的知识槽，NPC 的目标评分再读取这些带时效的信息决定是否重新观察、采集遗藏或巡逻。怀疑度达到阈值后，NPC AI 会优先调查、观察或避开玩家。这样“谁知道什么”成为世界状态，而不只是日志文本。

`src/social.js` 把交互从玩家 UI 回调提升为可复用的 Social Interaction runtime。帮助、施压、交易、交谈和调停都通过同一个 resolver 更新关系、记忆、状态效果、势力和事件账本；NPC-NPC 行动也调用同一入口。普通自治交谈保留在局部记忆，威胁/调停和玩家行为才升级为传闻传播，形成“局部交互 → 社会事件 → 势力情报”的分层成本模型。自治交互还带有行动者冷却，避免高人口区域在每个 AI tick 重复刷同一对话。

`src/consequence.js` 把失败、落败和主动忽略从一次性日志提升为持久后果账本。每条后果保存行动者、来源、地点、原因、结构化数据和时钟，并同步写入行动者的记忆、相关势力的后果索引、`facts.consequenceCounts` 与导演压力。当前演武落败、传承/巡逻/闯塔/梦境失败，以及导演事件的 `ignore/avoid` 选择都会留下可被存档、NPC 和势力系统读取的事实；这让“不行动”和“失败”真正改变后续世界，而不是只显示一行文字。

`src/identity.js` 在知识组件之上提供可运行的身份层：每个实体都有真实身份和若干公开面具，面具拥有公开姓名、角色、强度、覆盖故事、穿戴时间与已知者集合。玩家可以在行动目录或自然语言中切换“无名散修”面具、恢复真名或向同地点 NPC 摊牌；摊牌只改变目标 NPC 的知识，不会把真相广播给整个世界。市场事件可以记录面具痕迹，导演再根据追踪压力生成调查事件；调查压力同时进入相关势力的 NPC 目标评分，形成“传闻→案件→调查/伏击”的反馈回路。

动作也通过同一运行时注册。`src/gu-actions.js` 将委托接受/交付、商家城演武、三王传承闯关、北原巡逻、真阳楼闯层、内容驱动对话，以及等待、旅行、修炼、学习、采集、休息、炼蛊、装备、交谈、挑战和势力影响等基础动作注入 Action Registry；主 `action()` 只负责通用的冲突/世界事件门禁和调用注册表，不再维护一条按动作 ID 分叉的兼容链。动作前后钩子、行动目录和自然语言解析因此可以共享同一套世界规则。

地点交互进一步拆成 `src/gu-affordances.js` 的 Interaction Registry。一个区域不只是可移动到的背景，而是根据内容包在 `LOCATIONS[*].interactions` 中声明的能力，再结合资源、危险度、战区和当前实体状态暴露一组可执行 affordance：`observeZone` 记录局部观察和知识，`forage` 改变资源供给并制造竞争传闻，`searchRelic` 以洞察、危险和随机状态决定线索质量，`scoutZone` 把局部侦查转成战区压力变化。Action Catalog、自然语言意图、NPC 的 `observe / secureResources / findRelic / patrol` 目标和未来 AI 代理都提交同样的 `interact + affordanceId` 语义；NPC 通过 `executeForActor` 执行时不会偷走玩家时间，但仍产生同样的领域事件、资源竞争、记忆和后果。处理器仍必须经过 simulation kernel 校验，并统一推进玩家时间、触发领域事件、更新记忆和留下失败后果。这对应 Qud 中“实体/区域提供可组合事件响应”的边界，也避免把“观察/采集/搜索”重新做成固定剧情分支。

对话定义位于内容包的 `CONVERSATION_DEFS`，由 `src/conversation.js` 根据地点、旗标、时间和关系门槛筛选。选项后果不直接操作 UI，而是通过关系、势力、记忆和 History 账本写入世界状态。

委托定义同样只保留在内容包的 `CONTRACT_DEFS`；`src/contracts.js` 负责发现、目标判定、接受、完成和奖励。主模拟器只注入时间、关系、记忆、日志和推进回调，因此委托运行时可以被其他内容包复用。

重复行动也遵循同一边界。`src/repeatable-systems.js` 只接收引擎、随机源、关系/记忆/日志、伤害和时间推进回调，向主模拟器提供演武、传承、巡逻、闯楼、拍卖和梦境探索运行时。它们的资源、失败、领域事件和长期后果仍写入同一份世界状态，因此可以被 UI、自然语言意图和 AI 导演共享，而不会重新形成主模拟器的条件分支。

领域事件由 `src/engine.js` 同时写入待处理队列、有限长度的 `events.recent` 和有界的 `events.history` 账本。队列用于即时监听与消费，账本用于存档、回放和 UI 查询，避免“事件已处理”被误解成“事件从世界消失”；所有窗口都有明确上限，长跑时不会因为日志复制拖垮世界。`src/rumor.js` 订阅可传播事件，把同地点的交互、冲突、资源争夺和战线变化转成旁观 NPC 的记忆事实，并沿事件参与者所属势力的关系网传播；每次传播会保存 `eventId`、势力路径和置信度，并在 `state.intel.cases[subjectId].factions` 中积累案件压力。记忆因此可以通过空间和社会组织传播，而不要求每个 NPC 都直接参与行动。

第二卷的演武场和三王传承使用持续系统而不是一次性分支：`arena` 保存比赛、胜负、连胜和声望；`inheritance` 保存尝试次数、轮次、难度、发现和完成状态。第三卷的北原巡逻和真阳楼、第四卷的福地/宗门/拍卖链路、第五卷的 `worldWar` 五域战争状态同样保存跨区域状态。每次行动都经过同一个 dispatch、资源、伤势、记忆和历史管线。

第六卷终局链路使用独立的 `eternalWar` 状态保存神帝城、人道战线、两天重叠、疯魔窟、梦境压力、宇宙热度和星宿安排是否已经展开；梦境探索是可重复行动，不会被一次导演事件消费掉。

五域战争与两天终局事件会为 `coalitions` 预置不同质量的临时契约：南疆/西漠加入战争时生成补给和保护义务，天庭与两天势力的支援、渗透或破坏会改变合法性与凝聚力。事件只是打开一组谈判初值，之后的维持、失信和倒戈交给日级系统。联盟行动已进入 Action Registry 与意图解析，UI、自然语言和未来 AI 代理共享 `coalition_action`。

拍卖会的导演事件只负责打开市场，之后由 `auction_lot` ActionHandler 处理重复行动。玩家可以竞拍、观察行情、出售情报、抬价、抵押借元石或核验传闻；价格同时受热度和稀缺度影响，市场会记录供给、债务、信誉、情报可信度和交易追踪压力。每次行动都通过 `auction.lot` 领域事件更新区域活动、势力张力、旁观 NPC 传闻和玩家知识组件；这使“拍卖会”成为一个会自行变化、且会暴露行动者意图的系统，而不是一次性文本节点。

当面具下的交易痕迹达到阈值，内容导演规则包会生成 `identityPursuit` 调查局势。它不是预写的追杀分支：事件由 `central.tracePressure`、当前面具和冷却状态共同触发，结算仍通过统一事件注册表，结果可以降低追踪、污染情报可信度，或把市场和宗门紧张度推向更高层。

`src/pursuit.js` 把调查压力进一步物化为追捕队。队伍保存势力、目标、成员、线索置信度、推进度、热度和接触次数；成员拥有 `agent` 组件，是可以在地图上寻路、被观察、被收买或被误导的普通世界实体。小时系统独立推进追捕队，NPC 通用 AI 跳过 `agent`，避免代理人同时执行两套移动规则；玩家接触行动仍经过统一 Action Registry 和事件账本。

`src/agency.js` 提供另一种代理关系：玩家不用亲自执行每个行动，可以委托同地点 NPC 完成打探情报、侦查地点、代为交易或游说势力。委托保存代理人、目标地点、成本、进度、质量、截止时间和结果；代理人的当前位置、精力、人格、关系和所属势力都会影响结算。委托结果通过 `agency.commission_created` / `agency.commission_completed` 领域事件进入传闻、知识和 History，而不是直接把奖励写给玩家。

`src/market.js` 把交易从单个剧情动作提升为共享世界系统：清水、食物、月兰花瓣和遗藏碎片拥有基础价、供给、需求和价格；NPC 的 `trade` 目标与玩家的“代为交易”委托调用同一个 `quote/trade` 结算路径，直接改变库存、元石、供需、区域活动和势力影响。交易事件进入普通传闻和 `state.market.transactions`，但其案件压力为零，避免把日常商业活动错误升级成追杀线索；只有身份暴露、暴力和高风险市场痕迹才会推动追捕系统。

市场还为部分势力建立了可持久化的兴趣账本：商队优先补给并套利，商家城优先控制稀缺资源，古月一族优先维持山寨生存，北原部族优先战争后勤。NPC 的地点资源、所属势力政策和稳定人格扰动共同决定交易品类；交易量、势力库存倾向、金库和动机会写回 `faction.market`，从而让势力政策成为下一轮 AI 决策的输入，而不是静态标签。

这些兴趣现在属于 `src/content.js` 的 `FACTION_INTERESTS` 内容契约，不再由市场运行时独占定义。每个势力同时声明市场买卖偏好、资源偏置和战争动员/后勤压力；`market.js` 负责通用结算，`zone-runtime.js` 在离线居民交易、迁徙、巡逻、备战、资源再生和冲突摘要中读取同一份政策。替换小说内容包时可以更换势力经济和战争逻辑数据，而不必复制市场代码。

引擎现在还提供组件生命周期注册表和事件结算状态：组件可以声明 `ensure/onAttach/onDetach/onPatch`，事件监听器可以按优先级运行并把事件标记为 `handled/cancelled/consumed`。这为蛊虫、伤势、装备和身份部件提供了与 Qud `IPart`/`EventRegistry` 对齐的扩展点；现有内容仍保持兼容，未声明生命周期的旧组件按普通 JSON 组件运行。

玩家和 NPC 都使用相同的组件形状：

- `identity`：名字、角色、标签。
- `position`：地点与地点内部格点。`src/local-map.js` 为每个内容地点生成确定性的局部地形、障碍和四向出口；玩家用 `step` 行动逐格移动，走到边缘才触发区域迁移，旧存档由状态归一化补齐 `position.cell`。同一模块还提供曼哈顿距离和基于障碍的视线计算，前台只能渲染玩家视野内的实体。
- `localObjects`：地点内部的可发现对象由 `src/local-objects.js` 管理。对象拥有 `cell`、`kind`、`active`、`discovered`、`resolved` 和资源余量；只有在视野内才会出现在 Action Catalog，调查、靠近采集或追查分别写入区域发现、库存、记忆、情报 leads 和领域事件，旧存档会按内容种子补齐而不会把远方对象直接泄露给玩家。
- `needs`：精力、饥饿、安全感。
- `cultivation`：资质、境界、阶段、真元、修为。
- `personality`：野心、谨慎、忠诚、贪欲、好奇。
- `schedule`：默认日程，不是强制剧本。
- `goals`：当前目标与候选目标。
- `memory`：事实索引和带时间/情绪的事件记忆。
- `inventory`：资源和蛊虫组件。
- `equipment`：装备槽、蛊虫装载、部位约束和装备历史；可被能力与身体系统查询。
- `body`：生命、伤口和部位耐久；冲突系统只能通过伤害事件修改它。
- `effects`：可叠加、可过期、有来源和生命周期钩子的运行时效果实例；与仍保留的 `conditions` 兼容共存。
- `provenance` / `consequences`：跨事件来源链与持久失败后果的世界级账本，连接事件、记忆、势力、导演和存档。
- `abilities`：蛊术与技能能力槽，供行动系统消耗和验证。

`src/body.js` 把 Body 从普通 JSON 字段提升为可组合运行时：部位完整度、失能阈值、随机命中、伤口记录和治疗都有独立 API。`src/equipment.js` 进一步提供 Qud `Equipment`/装载部件边界：蛊虫可以占用槽位，装备记录装卸历史，并在装备时验证所需身体部位。`src/ability.js` 在发动蛊术时读取 Body 约束，因此伤势会改变可用能力，而不是只改变一条生命值；伤害结算仍通过 `combat.damage` 领域事件通知记忆、状态和势力系统。`src/effect.js` 则把效果实例从 Body/Combat 中拆开，允许后续把蛊虫副作用、环境危害、药效和临时修行状态接入同一套生命周期。

NPC 行为运行时位于 `src/npc-ai.js`。它只依赖组件查询、地点图、时钟、随机源和 GoalHandler 回调：先把恐惧、饥饿、安全感、性格、势力紧张、玩家关系和近期目标历史转换成效用分数，再沿地点图移动，最后执行目标并记录遭遇记忆。`src/gu-goals.js` 负责把资源争夺、遗藏调查、学堂竞争、保护关系和势力结盟等小说目标注册进 Goal Registry；目标完成后的社会交互或战斗由内容系统注入 `goalAction` 回调，AI 内核不再硬编码“哪些目标必须交谈/攻击”。因此同一 AI 层可以服务青茅山 NPC、北原部族或未来其他内容包；`goals.history` 会降低短期重复目标，避免 NPC 只按数组轮询。

`src/goal-handler.js` 是可恢复的目标栈运行时：`pushGoal`、`pushChildGoal`、`insertGoalAsParent`、`pop`、`moveTowards` 和 `takeAction` 对齐 Qud 的 GoalHandler/MoveTo/Wait 边界。NPC 每个 AI 周期只推进当前 handler 的一个步骤；移动未完成时不会提前执行目标，抵达后才调用注册的目标处理器，子目标完成后把控制权交还父目标。栈帧包含父子关系、阶段、尝试次数、最后动作时钟和结果，能够存档、审计和继续执行。

`src/default-goals.js` 提供内容包所需的通用目标处理器，例如学习、采集、巡逻、调查、招募、备战、疗伤和调停。它们会修改区域资源、危险度、势力影响、需求或记忆；`check-content` 会验证人口表和 NPC 种子中的每个目标都存在对应处理器。

`src/ability.js` 负责实体能力的学习、可用性和发动。蛊虫炼化完成后写入实体的 `abilities.gu`，战斗只请求能力运行时并消费真元，再通过 `ability.used` 领域事件写入历史；新增蛊虫不需要复制一整段战斗条件分支。

`factions` 和 `relationships` 独立保存，不能通过截断日志重建。这样玩家帮助方正、威胁漠北、向家族报告遗藏等动作，才会成为后续世界的事实，而不是一行已经消失的文字。

NPC 目标选择还会读取所属势力的紧张度和态度：战争压力高时，拥有对应目标的 NPC 会优先备战或巡逻；势力敌对时会优先规避玩家。势力因此不仅是 UI 数值，也会反向改变世界中人物的行为。

地点不是静态背景。`zones` 保存资源、天气、危险度、活动度、访问量和人口规模；人口表按地点类型生成环境居民，让竹林、河滩、商队营地和山寨在没有剧情事件时也能自行运转。资源采集、NPC目标和跨日恢复共同改变区域状态。区域运行时还保存活跃/挂起状态、离线小时、资源产出摘要和排队事件，使区域从静态背景升级为可缓存的世界容器。

局部对象是区域容器内的第二层模拟：内容包在 `LOCAL_OBJECT_SEEDS` 声明月兰花丛、山溪取水处、公告板、猎户脚印、旧血迹和遗迹石缝等对象，运行时为它们分配确定性格点。玩家必须先沿格点移动并获得视线，再通过 `local_interact` 调查、练习、采集或追查；对象的消耗、发现和解决状态会随存档保留。这样“我在世界里看见了什么”与“这个地点理论上有什么”被明确分开，也为后续动态事件导演提供可被玩家主动发现的局部触发器。

## 时间与 NPC

每个合法行动推进小时。时间推进触发：

1. 玩家需求、真元和修为恢复/消耗。
2. NPC 根据日程移动。
3. NPC 根据饥饿、恐惧、野心和世界压力选择当前目标。
4. 同场遭遇写入 NPC 记忆。
5. 跨日后结算需求、势力紧张度、导演压力和记忆衰减。

日程是“默认行为”，记忆和关系可以覆盖它；这使 NPC 不是静态对话点。玩家导航先在地点内部按 `position.cell` 逐格移动，走到局部地图出口才沿地点图迁移；NPC 的长期目标仍在地点图上逐区推进，因此跨地点目标不会瞬移，也不会因为不是直接邻居而失效。

NPC 目标还必须产出世界侧结果：采集会改变资源与势力影响，追查遗藏会增加共享压力，交易会改变商路活动，竞争会提高家族紧张度。日志只是这些事件的投影，不能代替状态本身。

## 事件和 AI 导演

事件分为两类：

- `action`：玩家提出的明确动作，由规则验证并结算。
- `director_event`：导演观察世界条件后生成的局势节点，例如竹林酒香、学堂竞争、商队消息。
- `combat`：实体间的连续冲突；攻击写入身体部位、伤口、死亡和对方记忆。

规则事件会写入带持久 `sequence` 的 `events.pending` 领域事件流，例如 `world.travel`、`npc.goal_action`、`social.interaction`、`combat.started`、`combat.exchange` 和 `combat.damage`。每个事件按 `before → resolve → after → settled` 阶段运行；监听器可按阶段和优先级注册，before 可以取消，resolve 可以消费，after 负责收尾。队列只保留最近窗口，但序列号不会回绕；外部导演、调试器或未来的回放系统可以消费这些事件，不需要解析 UI 日志。注册动作还支持 `before/after` hooks，当前用于记录动作指标，未来可以接入通用消耗、权限、冷却和反应规则。

运行时还提供事件监听器注册表。`src/gu-listeners.js` 将传闻传播、区域访问、演武、传承、战线、拍卖、交易和梦境压力注册为内容侧监听器；事件发出后，监听器可以为区域活动、危险度或统计账本添加派生后果。监听器不替代持久事件队列，而是把 Qud 式事件边界变成可组合的规则扩展点。

导演不能直接写玩家数值。它会先收集所有满足条件的候选规则，再按 `priority + score(state,event)` 选择，支持存档中的规则冷却与导演历史；`resolve_event` 仍经过同一个状态结算入口。当前导演已经覆盖遗藏线索、学堂竞争、商队进入、贾富拍卖会、三寨议事、狼潮逼近、三族大比武和铁家调查；后续五域与两天终局链也使用同一候选评分运行时。这些事件由时间、地点、势力紧张度、资源压力共同触发，而不是按章节顺序强制播放。将来接入语言模型时，模型只能生成候选意图/文案，不能绕过 `dispatch`。

导演还可以完全脱离章节日期产生涌现局势。当前 `coalitionFracture` 读取 `state.coalitions` 中所有紧绷盟约，按合法性、补给和凝聚力计算候选分数，只在玩家位于相关势力区域时开放；调停、补给、曝光和忽略由同一个事件处理器结算，并写回盟约、后果、玩家记忆和事件流。它与 `shadowNetworkExposure` 一样，是“状态阈值 → 候选事件 → 玩家行动 → 新状态”的闭环，用来防止 AI 导演退化成按卷章排队的脚本播放器。

## 小说迁移策略

第一阶段只迁移原文中有明确依据的青茅山开局：

- 方源重生与开窍大典前夜；
- 方正的孪生兄弟关系；
- 古月学堂、家老、竞争者和家族培养；
- 竹林、酒香、月光蛊、酒虫和花酒遗藏线索。
- 商队提前进入青茅山、贾富的市场博弈、三寨联盟和狼潮前的资源危机。
- 第二卷首批区域链：白骨山旅途、商家城演武场、三叉山三王传承、天梯山狐仙福地传闻。
- 第五卷首批区域链：影宗残脉重建、南疆超级家族、西漠房家、东海节点、天庭与长生天；五个跨域导演事件将它们接入持续战争热度和势力张力。
- 第六卷首批区域链：神帝城、书山、蛮荒大世界、黄土大世界、逆流河、梦境战场和疯魔窟；终局导演事件与重复梦境探索共同改变两天战场和天庭决策状态。
